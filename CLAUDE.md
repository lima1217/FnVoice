# FnVoice — agent notes

`make check` is the guardrail (tests, build, verify, live-path smoke); the pre-commit hook runs it once `make hooks` is set. The Makefile lists every other target.

Facts no config file shows:

- **Installed copy is what runs.** The user runs `/Applications/FnVoice.app` (also launched at login); a change reaches them only after `make install`.
- **Type first, swap later needs a readable field.** Whether a dictation types the raw text at once and swaps the LLM answer in (`InPlaceReplacer`) or waits for the LLM is decided at Fn-down by `EditWatcher.canReadFocusedField`; `make e2e` covers the swap and the skip in a real NSTextView, unit tests cover only the state machine.
- **TCC-bound modes launch via `open`.** `eval`, `bench`, `smoke` and `e2e` start FnVoice.app with `open -W`, so the app — not the terminal — holds mic, speech and Accessibility permission. New modes that touch those follow the same pattern.
- **Keychain prompts after every rebuild.** The signing identity is self-signed (no Team ID), so the Keychain tells builds apart by cdhash and asks for the login password the first time each new build reads the LLM key; "Always Allow" lasts only for that build. Only a normal launch (`AppController`) and modes that really call the LLM read the key; keep new test modes off `Keychain.readAPIKey` or pass `FNVOICE_LLM_API_KEY`.
- **Swap skipped in some app?** `make ax-probe TARGET=<app name>` reproduces what `InPlaceReplacer` sees there; `history.jsonl` records each dictation's target `app`, and `make eval-live` groups swap outcomes by it.
- **Logs:** `/usr/bin/log show --last 10m --info --predicate 'subsystem == "com.local.fnvoice"'`. Use the full path (zsh shadows `log`); `--info` is needed for everything except the `latency` line, which is logged at notice level so it survives restarts (info lines live only in process memory and are lost at every `make install`). Each dictation writes one `latency engine=… partials=… setup=… asr=… llm=… paste=… release→text=… cleanup=… replace=…` line; `partials` counts text updates while Fn was held (0 is normal for SpeechTranscriber, which reports nothing until release); `cleanup` is the injector's housekeeping after the text appeared (input source switched back, clipboard restored); `replace` is set when the LLM answer was swapped in after the raw text was typed.
- **Real usage data:** `history.jsonl` (see README › Privacy) has every dictation's texts, timings and the user's final edit; `make eval-live` replays it through current refinement. Its report holds the user's real text, so it stays git-ignored; never commit or paste it elsewhere.
- **Live path vs eval.** `make eval` transcribes files through a separate path; only `make bench` / `make smoke` run the live `AnalyzerSession`. Verify recognition changes there.
- **Nothing in `make check` opens the mic.** `bench` and `smoke` feed files, so they never see the first `AVAudioEngine.inputNode` access, which brings up CoreAudio's input path (~2 s cold, <60 ms afterwards for the process). `AppController.warmUpAudioInput` pays it at launch; `make coldstart` (quits the app, idles 2 min, presses Fn synthetically via `--first-press`) is the only check that would catch a regression, and it is too slow for the hook.
- **Menu-bar app text fields.** ⌘V/⌘C/⌘A route through `NSApp.mainMenu` even when no menu is visible, so every app target installs an Edit menu; windows call `NSApp.forceActivate()` to take keyboard focus.
- **Apple Speech and refinement quirks** (asset status, why `.fastResults` is off, two-analyzer interference, DeepSeek thinking, what `EditGuard` frees, keeps or puts back) are documented with measurements at their call sites in `Sources/FnVoice/AnalyzerCapture.swift`, `Sources/FnVoiceCore/LLMClient.swift` and `Sources/FnVoiceCore/Refinement.swift`; read them before changing recognition or refinement.
- **Prompt or guard changes** are judged by `make eval GATE=all` (otherwise the menu's scope decides which cases reach the LLM): false corrections must stay 0/32 and every `cleanup` case must match. LLM output varies run to run, so run it twice.
